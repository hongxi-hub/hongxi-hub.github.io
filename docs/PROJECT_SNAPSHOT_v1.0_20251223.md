### 一、项目概述
本项目基于克隆的 `vitepress-theme-curve` 主题博客进行全方位本地化改造。核心目标是**替换所有原作者身份信息、视觉资产及第三方服务依赖**，将其打造为完全个人拥有和控制的静态站点。项目采用 **`main`(源码)/`page`(部署) 双分支**模式，通过 GitHub Actions 自动构建部署。

### 二、技术栈与配置机制
- **生成器**：VitePress
- **主题**：curve
- **部署**：GitHub Pages (自动)
- **核心配置机制**：
    1. **双层配置**：存在 `./.vitepress/theme/assets/themeConfig.mjs` (主题默认) 与 **`./themeConfig.mjs` (用户自定义)**。
    2. **优先级**：构建时两者融合，**根目录的用户配置 (`./themeConfig.mjs`) 优先级更高**，会覆盖主题默认设置。所有用户层面的修改均应在此文件进行。

### 五、遇到的问题与解决方案总结
1.  **问题**：替换所有图标文件后，浏览器标签页图标 (`favicon.ico`) 不更新。
    - **根因**：`favicon.ico` 文件实际存放在 `./public/` 根目录，但配置中的引用路径 (`/favicon.ico`) 可能因部署原因未指向正确位置。
    - **解决**：
        - 确保文件已正确覆盖 `./public/favicon.ico`。
        - 在 `./themeConfig.mjs` 的 `inject.header` 中，核对 `href` 值是否为文件最终部署后的可访问路径。
        - 部署后，使用 **浏览器无痕模式** 或 **清除Site Data（含Service Worker）** 验证。
2.  **问题**：修改了 `main` 分支但网站 (`page` 分支) 迟迟未变。
    - **根因**：GitHub Actions 自动构建未触发、正在运行或失败。
    - **解决**：前往仓库 **“Actions”** 标签页，检查最新工作流状态。若失败需查看日志；若成功则等待分发（通常1-3分钟）。
